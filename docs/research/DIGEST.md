### TOPIC: Garmin Connect IQ Monkey C watch face (fenix 6, API 3.x) rendering/low-power behavior + Solana epoch countdown data flow

**Findings**

1. [high] On fenix 6 (a MIP/'always-active' display), onUpdate() is called at the top of every minute while in low-power mode, and once per second for ~10 seconds after a wake gesture (high-power mode). Separately, in always-active low-power mode, onPartialUpdate() (if implemented) is called once per second, subject to the device power budget.
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFace.html ; https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/changes-to-watch-face-low--and-high-power-modes ; https://forums.garmin.com/developer/connect-iq/f/discussion/7371/onpartialupdate-and-low-power-mode
2. [high] onEnterSleep() means 'the device is entering low power mode' — terminate active timers and prepare for once-per-minute updates. onExitSleep() means 'the device is exiting low power mode' — timers/animations may be started here, in preparation for once-per-second updates. Both are API level 1.0.0.
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFace.html
3. [high] onPartialUpdate() is API level 2.3.0+ (so available on fenix 6, API level 3.4). It must set a clipping region via dc.setClip() and touch as small a portion of the screen as possible. If its execution time exceeds the device's allotted budget, the system skips drawing that cycle and calls WatchFaceDelegate.onPowerBudgetExceeded(powerInfo as WatchUi.WatchFacePowerInfo).
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFace.html ; https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFaceDelegate.html
4. [medium] Garmin's official announcement states always-active (MIP) watch faces 'can perform a partial update of the screen every second' within a strict 20-millisecond budget per call. WatchFacePowerInfo exposes executionTimeAverage and executionTimeLimit (both Lang.Float, milliseconds), but the raw API doc page did not itself expose a documented numeric default for executionTimeLimit; the 20ms figure comes from Garmin's forum/FAQ summary content, not the API reference page directly.
   - src: https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/changes-to-watch-face-low--and-high-power-modes ; https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/WatchFacePowerInfo.html ; https://developer.garmin.com/connect-iq/connect-iq-faq/how-do-i-get-my-watch-face-to-update-every-second/
5. [high] fenix 6 / fenix 6 Pro / fenix 6 Sapphire / quatix 6 have screen resolution 260x260, screen shape 'round', and support Connect IQ / Monkey C API level 3.4. fenix 6S variants are 240x240, also round, API level 3.4.
   - src: https://developer.garmin.com/connect-iq/compatible-devices/
6. [medium] Graphics font constants are relative sizes, not fixed pixel values: FONT_XTINY=0, FONT_TINY=1, FONT_SMALL=2, FONT_MEDIUM=3, FONT_LARGE=4, FONT_NUMBER_MILD=5, FONT_NUMBER_HOT=7, FONT_NUMBER_THAI_HOT=8 (value 6 undocumented in the fetched page, possibly a deprecated/internal id). Actual per-device pixel heights for fenix 6 are not published on the official API docs page; Garmin's own community guidance is to measure at runtime with dc.getFontAscent()/getFontDescent()/dc.getTextDimensions(), or consult 'Appendix B' of the Connect IQ UX guide (not located/fetched in this pass).
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/Graphics.html ; https://forums.garmin.com/developer/connect-iq/f/discussion/348347/device-info-glance-yes-no-and-size-and-font-size-width-in-pixel ; https://forums.garmin.com/developer/connect-iq/f/discussion/5148/font-heights
7. [high] dc.drawArc(x, y, r, attr as Graphics.ArcDirection, degreeStart, degreeEnd) draws an arc; 0 degrees = 3 o'clock position, 90 degrees = 12 o'clock; attr is Graphics.ARC_CLOCKWISE or Graphics.ARC_COUNTER_CLOCKWISE. Available since API level 1.2.0, usable on fenix 6.
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/Graphics/Dc.html
8. [medium] dc.setPenWidth(width) sets stroke width for line/arc drawing (API 1.0.0); dc.setColor(foreground, background) accepts Graphics.COLOR_* named constants or raw 24-bit 0xRRGGBB values (API 1.0.0). The fenix 6 MIP display is a 64-color palette; documented COLOR_* constants: WHITE, LT_GRAY, DK_GRAY, BLACK, RED, DK_RED, ORANGE, YELLOW, GREEN, DK_GREEN, BLUE, DK_BLUE, PURPLE, PINK, TRANSPARENT. COLOR_PURPLE is documented as 'Not valid on fenix 3 or D2 Bravo' with no such caveat for fenix 6 (not independently re-confirmed beyond the doc text).
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/Graphics.html
9. [high] System.getClockTime() returns a System.ClockTime object (API 1.0.0); System.getSystemStats() returns System.Stats (battery property presence is commonly known/standard usage but the doc excerpt fetched did not surface the battery field text directly, so treat as not independently re-verified in this pass); System.getDeviceSettings() returns DeviceSettings with is24Hour (Boolean, API 1.0.0) and phoneConnected (Boolean, API 1.1.0).
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/System.html ; https://developer.garmin.com/connect-iq/api-docs/Toybox/System/DeviceSettings.html
10. [medium] Time.now() returns a Time.Moment representing UTC seconds since the Unix epoch; .value() returns that as a Number. Monkey C's Number type is a 32-bit signed integer, so Time.now().value() is subject to the standard Year-2038 rollover (mid-January 2038) — not an immediate concern for a 2026 project, but worth flagging if storing far-future absolute timestamps as Number rather than Long.
   - src: https://developer.garmin.com/connect-iq/api-docs/Toybox/Time.html
11. [low] No official Garmin documentation or forum evidence was found that the fenix 6 (round 260x260 / 240x240 MIP display) has a 'flat tire' (obscured/cropped) display region. The Connect IQ compatible-devices page lists fenix 6 / 6 Pro screen shape as plain 'round' with no caveat. This is an absence-of-evidence conclusion (no positive source found using the term 'flat tire' for fenix 6), not a directly cited Garmin statement.
   - src: https://developer.garmin.com/connect-iq/compatible-devices/ (screenShape=round, no caveat noted)
12. [high] Solana getEpochInfo RPC returns: epoch, slotIndex (slot index within current epoch), slotsInEpoch, absoluteSlot, blockHeight, transactionCount (nullable). Progress = slotIndex/slotsInEpoch; remaining slots = slotsInEpoch - slotIndex.
   - src: https://solana.com/docs/rpc/http/getepochinfo
13. [medium] Solana epoch length is fixed at 432,000 slots. Target slot time has historically been ~400ms, but mainnet slot time was cut to 350ms starting at epoch 1020 (~Aug 22, 2026) under SIMD-0525, with a further 200ms target planned. A fenix 6 watch face that hardcodes '400ms per slot' to extrapolate a countdown will be measurably wrong for the current epoch (2026-09-11 is after epoch 1020) — prefer deriving slot duration dynamically (e.g. from repeated getEpochInfo polling deltas or recent performance samples) rather than a hardcoded constant, or refresh often enough that drift stays small.
   - src: https://www.theblock.co/news/ecosystems/2026-08-22-solana-cuts-mainnet-slot-time-to-350-milliseconds-in-first-step-toward-200ms-goal-412521 ; https://forklog.com/en/solana-reduces-slot-time-to-350-ms/ ; https://solanavalidators.wiki/glossary/epoch/
14. [high] The proven open-source pattern for background web fetch + stale-data handling in a Monkey C watch face is warmsound/crystal-face: AppBase (CrystalApp.mc) checks staleness of stored data against Time.now().value() vs a stored fetch timestamp, sets a pending-request flag in Storage, calls Background.registerForTemporalEvent(...), implements getServiceDelegate() returning a Toybox.System.ServiceDelegate subclass tagged (:background), whose onTemporalEvent() calls Communications.makeWebRequest(...) and Background.exit(data) on completion; the app's onBackgroundData(data) merges results into Storage and calls Ui.requestUpdate(). Manifest requires <iq:uses-permission id="Background"/> and id="Communications"/. This app explicitly lists fenix6, fenix6pro, fenix6s, fenix6spro, fenix6xpro as supported products, with minSdkVersion 1.4.0 (app-wide) — confirming the pattern works on fenix 6 / API 3.x.
   - src: https://github.com/warmsound/crystal-face/blob/master/source/CrystalApp.mc ; https://github.com/warmsound/crystal-face/blob/master/source/BackgroundService.mc ; https://github.com/warmsound/crystal-face/blob/master/manifest.xml (fetched directly via raw.githubusercontent.com on 2026-09-11)

function checkPendingWebRequests() {
  // ...set pendingWebRequests[...] = true based on staleness checks like:
  // (Time.now().value() > (data["dt"] + 1800))  // 30 min staleness
  var lastTime = Bg.getLastTemporalEventTime();
  if (lastTime != null) {
    var nextTime = lastTime.add(new Time.Duration(5 * 60));
    Bg.registerForTemporalEvent(nextTime);
  } else {
    Bg.registerForTemporalEvent(Time.now());
  }
}

function getServiceDelegate() { return [new BackgroundService()]; }

function onBackgroundData(data) {
  // merge into Storage, clear pending flag, Ui.requestUpdate()
}

// BackgroundService.mc
(:background)
class BackgroundService extends Sys.ServiceDelegate {
  (:background_method)
  function onTemporalEvent() {
    makeWebRequest(url, params, method(:onReceiveX));
  }
  (:background_method)
  function onReceiveX(responseCode as Number, data) {
    Bg.exit({ "X" => (responseCode == 200) ? data : {"httpError"=>responseCode} });

  (:background_method)
  function makeWebRequest(url, params, callback) {

      :headers => {"Content-Type" => Communications.REQUEST_CONTENT_TYPE_URL_ENCODED},
      :responseType => Comms.HTTP_RESPONSE_CONTENT_TYPE_JSON
    };
    Comms.makeWebRequest(url, params, options, callback);
  }

**Pitfalls**

- Watch faces cannot reliably do live foreground HTTP fetches during onUpdate/onPartialUpdate; the Garmin-sanctioned pattern is a Background ServiceDelegate fired via Background.registerForTemporalEvent(), which runs briefly, does the HTTP call, and calls Background.exit(data); the main app receives it via onBackgroundData(). Build the Solana RPC fetch this way, not as a naive foreground call.
- onPartialUpdate has a very tight execution budget (per Garmin's forum/FAQ guidance, ~20ms per call, covering your code execution + graphics draw + display flush combined) and must use dc.setClip() to limit the redrawn region — a full-screen or unclipped drawArc/drawText call there will likely exceed the budget and trigger onPowerBudgetExceeded, silently skipping that second's update.
- The exact numeric millisecond budget for WatchFacePowerInfo.executionTimeLimit was not confirmed as a documented constant on the API reference page itself (only property names/purpose confirmed); treat any specific ms number (e.g. 20ms) as sourced from secondary community/FAQ content, not a guaranteed hard API contract — read executionTimeLimit at runtime instead of hardcoding it.
- Do not hardcode Solana's ~400ms/slot assumption for countdown extrapolation — mainnet slot time changed to 350ms at epoch ~1020 (around Aug 22 2026) per SIMD-0525 and may change again toward a 200ms target; a fenix 6 app that assumes a fixed slot duration for extrapolating time-to-next-epoch between RPC fetches will drift.
- Per-device pixel heights for FONT_NUMBER_THAI_HOT/HOT/MILD etc. specifically on fenix 6 were not found in an authoritative, directly-citable Garmin table during this research pass; only generic relative-size descriptions were confirmed from the official Graphics module docs. Measure with dc.getTextDimensions()/getFontAscent()/getFontDescent() at build/runtime (simulator with -d fenix6/fenix6pro) rather than trusting an assumed pixel number.
- Monkey C's Number type is 32-bit; watch for Solana RPC u64 fields (transactionCount, absoluteSlot) potentially needing Long rather than Number depending on API level/magnitude, and for Time.now().value() 2038 rollover if you ever do far-future absolute-time math.

- Garmin's official developer.garmin.com pages are a Gatsby SPA and return only nav-menu text to naive scrapers/WebFetch; the real article HTML lives at a parallel, directly-curlable path: https://developer.garmin.com/connect-iq/articles/<folder>/<PageName>.html (derived from each page's /page-data/<path>/page-data.json, whose pageContext.file gives the underlying static HTML filename). - Device definition files require an actual Garmin account login (OAuth via SSO) per the community CLI's source code — there is no public anonymous device manifest equivalent to sdks.json. Plan for credential handling (GARMIN_USERNAME/GARMIN_PASSWORD) in any headless CI setup, and be aware this is unofficial/reverse-engineered API usage (api.gcs.garmin.com), not a documented public API — it could break without notice.
